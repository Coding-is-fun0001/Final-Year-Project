================================================================================
BENIGN RANSOMWARE SIMULATOR - COMMAND REFERENCE
================================================================================

IMPORTANT: 
  - Always point --target at a dedicated TEST folder (name must contain 'test' or 'sandbox')
  - Never run on real data or system directories
  - Use in isolated VM ONLY
  - Commands execute in order: --setup → --run → --restore

================================================================================
STEP 1: CREATE BASELINE TEST FILES
================================================================================

WINDOWS:
  python benign_ransomware_simulator.py --target C:\ransom_test --setup

LINUX/MAC:
  python3 benign_ransomware_simulator.py --target ~/ransom_test --setup

Result: Creates 80 dummy test files with low entropy in the target folder.

================================================================================
STEP 2: SIMULATE THE RANSOMWARE ATTACK
================================================================================

WINDOWS:
  python benign_ransomware_simulator.py --target C:\ransom_test --run

LINUX/MAC:
  python3 benign_ransomware_simulator.py --target ~/ransom_test --run

Result: 
  - All 80 files get XOR-encrypted (content becomes garbage/unreadable)
  - All files renamed with .locked extension (e.g. testfile_001.txt.locked)
  - Ransom note dropped: READ_ME_TEST_NOTE.txt
  - Metadata saved: .simulator_metadata.json (contains the XOR key)

Your FYP_near_proposal.py detector should now trigger alerts for:
  ✓ Rapid file events (80 files in ~0.6 seconds)
  ✓ Suspicious extension change (.locked)
  ✓ Entropy spike (binary garbage has high entropy)
  ✓ Hash mismatch (content changed)

================================================================================
STEP 3: RESTORE ALL FILES (REVERSE THE SIMULATION)
================================================================================

WINDOWS:
  python benign_ransomware_simulator.py --target C:\ransom_test --restore

LINUX/MAC:
  python3 benign_ransomware_simulator.py --target ~/ransom_test --restore

Result:
  - All *.locked files XOR-decrypted and reverted to original names
  - Original content fully restored (byte-for-byte identical)
  - Ransom note deleted
  - Metadata file deleted
  - Folder back to pre-attack state

================================================================================
WHAT IS THE "PASSWORD"?
================================================================================

There is no password to enter. The XOR key (0x5A) is automatically:
  - Used to encrypt files during --run
  - Stored in .simulator_metadata.json inside the test folder
  - Automatically read during --restore

So --restore is completely automatic — just run the command with no password needed.

If you delete the .simulator_metadata.json file, --restore won't work, so:
  ⚠️  Don't delete .simulator_metadata.json before running --restore
  ⚠️  Keep the metadata file safe until restoration is complete
